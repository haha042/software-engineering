## 二、关键接口契约（模板 D）

### API-01 / 下单（正常、业务失败、重复请求）

| 项目 | 内容 |
| --- | --- |
| 接口编号/名称 | API-01 / 创建订单 |
| 需求与决策依据 | UC-11、BR-04/12/21、DC-02/03/08；Q-01/Q-04/Q-08；ADR-004/008 |
| 方法与路径 | `POST /api/orders` |
| 调用者及权限 | 已认证学生（`auth(req,'student')`）；账号非限制期；非参与者不可代下单 |
| 请求 | body JSON：`requestKey`（8～100 字符，必填）、`productId`（必填）、交换类另需 `offer{title,description,condition,images}`、`topup`（0～99999.99）、`payer`（buyer/seller，差价非零时必填）。当前**不接收** `productVersion` |
| 成功响应 | `201 {id}`；`orders.status='pending'`，`deadline=now()+48h` |
| 失败响应 | 400 参数/图片/差价方向；401 未登录；403 本人商品或限制期；409 商品不可交易、请求键用于不同参数；500 未预期异常。错误码语义未确认（Q-04） |
| 前置与后置 | 前置商品 `status='live'`；成功后商品 `reserved`、写 create 事件、向卖家发 outbox 通知；不得产生半笔订单 |
| 并发与幂等 | `UNIQUE(buyer_id,request_key)`：同键同参数返回原 id，同键不同参数 409；`one_active_order` 部分唯一索引兜底跨用户竞争 |
| 事务 | `tx()`（`BEGIN IMMEDIATE`）内含查重、校验、插入、锁商品、事件与 outbox；通知在事务提交后投递 |
| 隐私 | 仅买卖双方可见订单详情；真实姓名/学号不进入订单响应 |
| 测试关联 | TC-01、TC-04、TC-05、TC-13 |
| 确认 | 提供方 / 调用方 / 复核人：未指派；版本 草拟 |

## 三、关键详细设计（只写难点）

### 3.1 订单状态转换（据 `main` 源码）

```
pending ──accept(seller,未超时)──> delivery ──deliver(seller)──> confirmation ──双方confirm──> completed
   │ reject(seller) -> closed        │ cancel/agree_cancel -> cancelled        │ 7天提醒(notice)
   └ cancel(buyer) -> cancelled      └ request_cancel -> cancel_status=pending
                                        ├ withdraw_cancel -> withdrawn
                                        ├ deny_cancel -> denied
                                        └ agree_cancel -> agreed 且 status=cancelled
超时: pending && deadline<=now && paused=0 --expire()--> closed + release(product)
```

不变量：进行中订单（`pending/delivery/confirmation`）每商品至多一笔（`one_active_order`）；取消申请未决时不得 deliver；封禁/暂停订单不得迁移。

### 3.2 数据库唯一约束（负载在 DB 层）

| 约束 | 表/列 | 保证 |
| --- | --- | --- |
| `UNIQUE(buyer_id,request_key)` | orders | 同买家同请求键只一笔订单 |
| `one_active_order` 部分索引 | orders(product_id) | 同商品只一笔进行中订单 |
| `UNIQUE(sender_id,request_key)` | messages | 私信幂等 |
| `PRIMARY KEY(user_id,event_key)` | notification_outbox | 通知去重 |
| `UNIQUE(user_id,product_id)` | favorites | 收藏不重复 |
| `UNIQUE(product_id,buyer_id,seller_id)` | conversations | 会话不重复 |
| `one_pending_cert`、`unique_student_identity` | certifications | 待审唯一、已通过学号唯一 |

### 3.3 事务边界与锁顺序

- 所有写业务走 `tx()`（`BEGIN IMMEDIATE` 取得写锁）→ 单写者模型，避免死锁。
- 订单：先查 `request_key` → 校验商品/权限 → 插入订单 → 锁商品 → 写事件/outbox → COMMIT → flush 通知。
- 通知 `notice()` 只写 outbox（冲突忽略），**不在业务失败路径投递**；`flushNotifications()` 在 `tx()` 成功返回后执行，失败只记日志。
- 事务外副作用：HTTP 响应、日志、静态文件读取；均不参与回滚。

### 3.4 幂等与超时重试

- 请求键为业务幂等键；同键同参数返回原结果、不同参数 409。
- 通知 outbox 的 `delivered_at IS NULL` 行由每次 `tx()` 后及启动时 `flushNotifications()` 重试；去重由 `(user_id,event_key)` PK 保证。
- 订单过期由 `expire()` 每 60 秒扫描；暂停订单跳过；重启时 `createApp` 后 interval 首次执行会补处理。

### 3.5 权限矩阵（服务端强制）

| 资源 | 访客 | 已认证学生 | 管理员 |
| --- | --- | --- | --- |
| 公开商品列表/详情 | 只读 live | 只读 live | 全部 |
| 发布/下单/订单动作 | 禁止 | 本人范围 | 只审核/处置，不代下单/确认 |
| 图片 `/api/images/:id` | 仅 live 商品 | live 或本人或订单参与者 | 全部 |
| `/api/admin/*` | 禁止 | 禁止 | 允许并写 audit |
| 私信会话 | 禁止 | 仅会话双方 | 不可读（C07 差异） |
