## 1. 现状（确认前的事实）

| 位置 | 现状 |
| --- | --- |
| `业务系统/src/database.js:10` | `products.category TEXT NOT NULL`，自由文本，无长度上限校验以外的约束 |
| `业务系统/src/database.js` | 没有 `categories` 表，也没有迁移表结构 |
| `业务系统/src/admin.js` | 没有分类相关路由，管理员无法维护分类 |
| `业务系统/src/products.js` | 发布时 `text(b.category,1,40)`，任意字符串都能落库 |
| `业务系统/public/products.js:16` | 发布页「分类」是一个文本输入框（`placeholder="如：书籍教材"`） |

因此「停用分类」目前无处可停用，历史商品也没有稳定的分类标识可比对。

## 2. 结论一：分类标识

采用「单级分类表 + 商品引用 id + 保留历史文本」的过渡方案，理由是：不破坏既有数据字节、不需要一次性重写商品行、筛选可以按 id 稳定命中。

```sql
CREATE TABLE IF NOT EXISTS categories(
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL UNIQUE,
  status TEXT NOT NULL DEFAULT 'active',   -- active | disabled
  sort INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL,
  disabled_at INTEGER
);
```

- `products` 新增 `category_id INTEGER REFERENCES categories(id)`；旧的 `category TEXT` **保留不删**，作为下单/展示时的历史快照兜底。
- 历史数据迁移（启动时幂等执行，失败不影响启动，只记录告警）：

```sql
INSERT OR IGNORE INTO categories(name,status,sort,created_at)
  SELECT DISTINCT category,'active',0,? FROM products WHERE category<>'';
UPDATE products SET category_id=(SELECT id FROM categories c WHERE c.name=products.category)
  WHERE category_id IS NULL;
```

- 对外标识统一用 **`categoryId`（整数）**；`category` 字段保留为分类名称，只读展示，不再作为写入入参。
- 列表与详情响应同时返回 `categoryId` 与 `category`（名称），前端不必二次查询。

## 3. 结论二：停用后的旧商品

| 场景 | 行为 |
| --- | --- |
| 已上架商品所属分类被停用 | 商品状态不变，**不自动下架、不通知、不留处置记录**（停用是分类维护，不是违规处置） |
| 详情页、我的发布、订单快照 | 仍显示原分类名称；分类停用后不显示成「未分类」 |
| 商品列表筛选下拉 | 只列 `status='active'` 的分类，停用分类不出现 |
| 按 `categoryId` 过滤且该 id 已停用 | 允许命中历史商品（保证历史可查），返回结果与停用前一致 |
| 按分类名称 `category=教材资料` 过滤 | 仅接受 active 分类；停用分类按「无此分类」处理，返回 `400 分类不存在或已停用` |
| 编辑商品 | 分类下拉同样只列 active；原分类已停用时，商品可改到其他 active 分类，不能原地重提原分类 |

## 4. 结论三：发布与编辑接口的错误响应

写入接口（`POST /api/products`、后续 `PATCH /api/products/:id`）统一在**事务开始前**校验分类，校验失败一律不创建、不修改任何数据：

| 场景 | 状态码 | 响应体 | 是否落库 |
| --- | --- | --- | --- |
| 未传 `categoryId` 或为空 | 400 | `{"error":"请选择分类"}` | 否 |
| `categoryId` 不是正整数 | 400 | `{"error":"分类不存在"}` | 否 |
| `categoryId` 在表中不存在 | 400 | `{"error":"分类不存在"}` | 否 |
| `categoryId` 已停用 | 400 | `{"error":"分类已停用，请重新选择"}` | 否 |
| 兼容期仍传 `category` 文本 | 400 | `{"error":"请使用 categoryId 选择分类"}` | 否 |

兼容期策略：过渡版本同时接受 `categoryId` 与 `category`（名称），仅当名称能唯一匹配到 active 分类时视为成功；两个字段同时传且冲突时以 `categoryId` 为准，并在响应里返回实际分类。过渡期结束后移除名称入参。

## 5. 需要与 C01（商品筛选）对齐的三点

1. **查询参数名与类型**：筛选统一用 `categoryId`（整数，可重复传多个）还是 `category`（名称）？本方案建议 `categoryId`，与发布入参一致，避免中文名称在 URL 编码上的歧义。
2. **停用分类在筛选项里的呈现**：本方案建议「下拉不出现、按 id 仍可命中」；若 C01 希望下拉保留但置灰，需要额外返回 `status` 字段。
3. **列表响应字段**：本方案返回 `categoryId` + `category` 两个字段；若前端已有按名称渲染的逻辑，需要同步改一处 `public/products.js`。
